# Append records to an existing table

After importing an external source, open its local table and choose **External Data → Append Records**. Select a destination table and map each source field using **Append source field** and **Append to field**. Matching names are preselected except AutoNumber; skipped destination fields receive their defaults, generated AutoNumber/GUID values, or null. Explicitly map an AutoNumber to preserve its source values, subject to uniqueness. Destination types and constraints remain authoritative. The current filtered/sorted view is the source; the source table is not modified unless it is also the selected destination. Self-appends read only the original view.

The confirmation defaults to Cancel. Any conversion, uniqueness, relationship, row/character-limit or source-enumeration failure publishes nothing. The entire successful append is one undo step. Unlike Access action queries, DataSpace retains bounded in-memory undo. Validation failures keep the mapping dialog open. This is a local staged append, not a direct remote append/import stream or source write-through operation.

The reusable `DatabaseWorkspace.AppendRecords` method takes destination column names and positional rows, an optional expected revision, cancellation token and retained-character budget (default 16,777,216 UTF-16 characters). It copies schema/list containers but shares untouched old record dictionaries and normalizes only incoming rows. It still scans applicable uniqueness and relationship constraints; no persistent database index is created. A stale dialog also checks document identity before applying, so replacing a database with a matching revision cannot accept the old draft.
